**Decision:** `pcf.experts.context_retro` gives a chain of expectations for every dropback from 2017 on, made after the season: before the snap (**E0**) and given the real pressure (**E1**), for six outcomes (pressure, time to throw, sack and dropback yards per dropback; depth of target and completion per attempt). From the sack's two it splits each sack over expected into a **pressure part** (E1 − E0) and an **after-pressure part** (sack − E1), summed per passer and lineman per game. Outputs: `outputs/context-retro/<run_id>/history.parquet` (standard schema, cadence `retrospective`) and `player_game.parquet` beside it; MLflow experiment `context-retro`; champion `pcf.context-retro`.

## The brief's calls, as built

1. **Trees with context-live's settings** (`context_live.models.fit`), the fields missing in seasons that don't have them (FTN's calls before 2022).
2. **The provider rule** (decision 0038's): pressure and time to throw, and every E1 model, train within a provider: test seasons through 2023 from 2016, 2024 on 2023, 2025 on 2023-2024 (`run.train_window`). E0 for the play-by-play's outcomes (sack, depth, completion, dropback yards) trains on every season from 2016.
3. **A sack counts as a pressure**; a dropback with no pressure flag is left out of every E1 model and has E0 only (`plays.with_pressure`).
4. **The main team's tie-break is fixed:** most games, then the team code first in the alphabet (`pcf.validation.owners.main_team`), so share kept is the same on every run.
5. **The ladder:** E0 the training mean → linear → trees; E1 the pressure alone → linear → trees. A rung is kept only if it beats the one kept below it on the whole 90% interval of the paired difference by week.

## Claude's calls from the build

6. **Its own runner**, like context-live (decision 0036): it describes plays that happened, so it reuses the harness's pieces (the paired comparison by weeks, calibration, the vault rule, the vintage check) rather than the harness's game-level runner.
7. **Coverage is read only from 2023 for outcomes whose plays include sacks** (`dcov_*`, `dman`). Before 2023 participation leaves coverage empty on every sack (100% of sacks in 2018-2022, against about 5% of other dropbacks), so trees learn "no coverage, so a sack" and the rule turns over in 2023 (BUILD.md, the smoke run: sack E0 worse than the average, calibration slope −0.68). Pass attempts keep coverage from 2016 (it is missing on 0.3% of them, completed at the usual rate).
8. **Missing rusher counts are filled with 4, and a missing box with 6.** In 2016-2017 participation has no rusher count on 1,447 dropbacks, sacked 0.1% of the time against 6.1%: the gap itself marks non-sacks. FTN's zero rushers with a box of 2 or fewer is read as not charted (null).
9. **Recalibration rule, set before the run:** a shipped chance that fails the calibration bar (error over 3 points, or slope outside 0.9-1.1) is refit with Platt scaling inside each training window; the recalibrated version ships only if it passes and its log loss isn't clearly worse. Otherwise the raw rung ships and the failure is reported.
10. **The null is scored on the mean:** E0's shipped rung refit 20 times on outcomes shuffled within each season-week, scored by log loss for a chance and squared error for an amount. Fields that are empty in a training window are dropped from the null's fit (a tree can't bin an all-missing column).
11. **The passer is the passer or, on a scramble, the rusher** (dropbacks only: designed runs aren't in the population).
12. **Linemen are participation's on-field offensive linemen** (C, G, T) on each dropback, so a lineman's game total counts every dropback he was on the field for.
13. **The rows' `as_of` is the later of the game's (context-live's 14-day moment) and participation's release** (the day after the Super Bowl). Retrospective, so it feeds an in-season model only from completed seasons, as a prior (rule m).
14. **The split's measures use the shared yardstick** (`pcf.validation.owners`): repeat (season to next season, players over a floor: 150 dropbacks for a passer, 300 for a lineman) and share kept by movers, with a 90% interval from 2,000 resamples of players. Context-v2's fourth look is the method; the module is new and shared so skill-over-expected and later projects read the same numbers.
15. **H88's test design** (pre-registered in BUILD.md before any H88 code): four arms (plain, live = context-live's calls16 back-history run `b68c042b`, retro, retro+ with the split), each a passer's or offense's season over-expected rate on five shared outcomes, pulled toward 0 by 100 plays, put on next season's rows only once known; scored on the crude forecaster's four yards boards (passing and team, next game and rest of season), 2019-2024, lasso (decision 0037). The vault stays closed for the crude forecaster.
16. **Idea I72 applied** (the old provider's empty pressure flag on sacks): it is the reason for call 3.
17. **Not used:** schemes-v2's traits and personnel strings (context-live R4, R18: no gain, and personnel coding changes in 2023). Only dropbacks are modeled; rushing plays are context-live's.
18. **The champion** is each outcome's shipped rungs fitted on every season through 2025 (inside the provider rule), as one model keyed by quantity, registered only if every check passed. A retrospective expert has no live output: next season's rows are scored after that season.
